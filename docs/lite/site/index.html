First, the plain-English version

Not another dashboard.
A second look at your logs.

Logs are scattered across services and formats. During an incident, the hard part is not finding a red line—it is understanding which events are connected, what they support, and what remains uncertain.

Lite keeps the original evidence close, connects only what it can justify, and turns deterministic signals into reviewable incident hypotheses.
⌁
Bring what you have

Application, container and file logs. No instrumentation retrofit.

⟷
Keep connections honest

Trace, request, entity and parent/child edges remain distinct.

◎
Inspect the evidence

Findings are hypotheses, with references and limitations.

▣
Own the runtime

Self-hosted components, durable work, no cloud AI dependency.

Inside the engine

Five gates. Each has one job.

Every stage works from durable queue items. It can retry, recover, and advance transactionally—without an unbounded in-memory queue.

01 / NORMALIZE

Shape the event

Map formats into a canonical event. Preserve original text and provenance.

02 / QUALITY

Expose uncertainty

Missing, inferred, unmapped or conflicting fields are marked—not invented.

03 / CORRELATE

Connect evidence

Trace, request, entity and parent/child relationships stay separate.

04 / DETECT

Find signals

Errors, failed outcomes, latency, retries and invariant signals.

05 / REASON

Explain a likely cause

Evidence-linked hypotheses, alternatives, uncertainty and limitations.

Durability built into the path

TimescaleDB journal · leased work · retry/backoff · idempotent processing · bounded queue · recovery.

Small, deliberate runtime

Fluent Bit → HTTP ingest/brain → TimescaleDB. No Kafka, Redis/Valkey or LLM on the ingestion path.

Operational transparency

Measure what happened.
Don't trust a green badge.

Lite currently exposes health and collector metrics. Findings and queue state are inspected in the database, so here is what to check.

01 / COLLECTOR

Fluent Bit's own metrics

Check the collector endpoint. Metric names depend on the installed build.

curl -s http://localhost:2020/api/v1/metrics/prometheus
02 / HEALTH

Brain is responding

Health proves the process responds—not that all stages have drained.

curl -i http://localhost:4000/health
03 / JOURNAL

Accepted versus persisted

Compare your sent record count with the raw journal.

SELECT count(*) FROM lite_raw_records;
04 / FINDINGS

Review the evidence links

Findings are currently available directly in TimescaleDB.

SELECT title, likely_cause, confidence,
       affected_services, occurrence_count,
       first_seen, last_seen, evidence
FROM lite_findings
ORDER BY last_seen DESC LIMIT 20;
Accuracy is a separate evaluation. To measure detection quality, compare against isolated ground truth: true/false positives and negatives, root cause versus symptoms, service and tenant isolation, evidence quality, confidence and detection delay. Do not ingest the evaluator labels.
Get hands-on

Run it on your machine.
Send one log. Inspect it.

Quick path for local exploration. Docker Compose is currently the supported local stack. Ports bind to localhost; use private networking or TLS ingress before remote exposure.

STEP 01 / GET THE SOURCE

Clone Lite

Get the branch that contains the standalone runtime.

git clone https://github.com/darshanredkar11/observalog.git
cd observalog
git checkout lite/chaos-gate-3-5
STEP 02 / CONFIGURE

Set a secret

Copy the example environment file and replace the ingest token with a random secret (at least 24 bytes).

cp .env.example .env
# edit LITE_INGEST_TOKEN
set -a; . ./.env; set +a
STEP 03 / START

Bring up the stack

Build and start the three local components. Check health before sending.

docker compose up -d --build
curl -fsS http://localhost:4000/health
Send a sample event to the raw ingest endpoint

A successful HTTP 202 means the raw record and its first work item were committed durably.

curl -X POST http://localhost:4000/ingest/raw \
  -H 'Content-Type: application/x-ndjson' \
  -H "X-ObservaLog-Token: $LITE_INGEST_TOKEN" \
  -H 'X-ObservaLog-Source: checkout-service' \
  --data-binary '{"timestamp":"2026-11-25T12:00:00Z","level":"ERROR","service":"checkout","trace_id":"t-001","message":"Payment provider timed out","error_code":"UPSTREAM_TIMEOUT"}'
Tail local files automatically

Fluent Bit tails ./var/logs/*.log. Container stdout/stderr is also tailed on Linux hosts where Docker logs are accessible.

mkdir -p ./var/logs
echo '{"timestamp":"2026-11-25T12:00:00Z","level":"INFO","service":"demo","message":"hello from file"}' >> ./var/logs/demo.log
Check the queue and persistence after ingest

Inspect the schema, then check queued, leased, completed and dead work. The brain has no findings dashboard/API yet.

docker compose exec timescaledb psql -U observalog -d observalog -c "\\d lite_gate_work"

Honest boundaries

What Lite can—and can't—say.

Trust comes from knowing where the evidence ends.

Hypotheses, not verdicts

Correlations and deterministic signals can suggest a cause. They cannot guarantee causality.

No live findings UI (yet)

Use SQL to review findings and queue state. The site does not simulate a live dashboard.

Keep ingestion private

Token authentication is not encryption. The endpoint is HTTP; don't expose it publicly without trusted network or TLS.

Evaluator truth stays separate

Known labels are for evaluation only. They must never enter the live brain's ingest path.
