What is it?

Understand failures
that span multiple logs.

Keep your current logging. Lite makes the raw evidence more useful without pretending missing information exists or turning coincidence into causality.

INPUT

Existing logs

JSON, JSONL, nested OpenTelemetry-style fields, Java/Spring, Node/Pino, Python text, Nginx, PostgreSQL, key/value and plain text.

ANALYSIS

Evidence links

Trace, request, business-key and parent/child relations remain separate. Missing IDs stay unknown; conflicting joins are flagged.

OUTPUT

Incident hypotheses

Deterministic signals group into evidence-backed explanations, with alternatives, uncertainty and event references.

Pipeline

Five gates. One traceable path.

Each gate is an independent durable worker backed by TimescaleDB. Work is leased, retried and advanced transactionally.

Raw input→Normalize→Quality→Correlate→Detect→Reason
GATE 1

Normalize

Map heterogeneous records to canonical events while retaining original text and provenance.

GATE 2

Quality

Mark missing, inferred, unmapped or conflicting fields; no silent fabrication.

GATE 3

Correlate

Connect trace, request, entity and span relations without collapsing distinct identity types.

GATE 4

Detect

Signals for errors, failure outcomes, slow events, retries, payloads and business invariants.

GATE 5

Reason

Evidence-linked hypotheses, alternatives, uncertainty and explicit limitations.

DURABILITY

Recoverable work

Persistent queue, leases, bounded backlog, retry/backoff, idempotency and recovery support.

Usage guide

Get it running in four steps.

Local run requires Docker Compose v2. Ports bind to localhost. Use a private network or TLS ingress before any remote exposure.

Post-run metrics

Verify persistence, drain and findings.

Use collector metrics and database checks after the run. The Lite brain currently has no public metrics dashboard or findings API.

① Fluent Bit metrics

Collector Prometheus endpoint. Inspect metric names emitted by the installed version.

curl -s http://localhost:2020/api/v1/metrics/prometheus

② Brain health

Process responds; this alone doesn't mean the gates have drained.

curl -i http://localhost:4000/health

③ Persisted raw count

Compare the number accepted with the raw journal count.

docker compose exec timescaledb psql -U observalog -d observalog -c "SELECT count(*) FROM lite_raw_records;"

④ Recent findings

Inspect hypothesis output directly in the database.

SELECT title, likely_cause, confidence,
       affected_services, occurrence_count,
       first_seen, last_seen, evidence
FROM lite_findings
ORDER BY last_seen DESC LIMIT 20;

⑤ Gate queue state

Check the table schema first, then inspect queued, leased, completed and dead work/attempts in the current schema.

docker compose exec timescaledb psql -U observalog -d observalog -c "\\d lite_gate_work"

⑥ Performance report checklist

Record input and persisted counts, finding count, backlog/dead work, retries, processing duration, ingest throughput, p50/p95/p99 latency, CPU/RAM, collector errors and queue drain time. Repeat across seeds and arrival permutations.

Metric honesty: Collector metrics come from Fluent Bit. Operational backlog and finding data are currently inspected in TimescaleDB; detection accuracy (TP/FN/FP, root cause vs symptoms, isolation, confidence) requires the separate evaluator and isolated ground-truth labels.

Limitations & safety

What Lite does not claim.

Not guaranteed RCA

Correlation and evidence support a hypothesis—not proof of causation.

No findings UI yet

Review hypotheses via SQL. This page is a guide, not a live dashboard.

Private ingest

Token auth is not encryption. The endpoint is plain HTTP; keep it trusted or behind TLS ingress.
